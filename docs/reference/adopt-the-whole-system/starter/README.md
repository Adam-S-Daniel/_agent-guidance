# Starter code for "Adopt the whole self-improvement system"

Tested starter code for the repos the guide ([`../README.md`](../README.md))
has you create. Each subfolder is one destination. Copy a subfolder's contents
into the root of that repo (`../bootstrap/copy-starter.sh` does it through a
pull request and fills `<you>` for you), replace the other placeholders listed
below, and run its tests there.

The reference versions the guide links to are fuller than this: they carry
more checks, more workflows, more tests and the history behind them. This
folder is the smallest set that works, matches the guide's listings, and
tests itself.

that and the bootstrap suite. `.gitattributes` keeps every
file LF, which the hooks need (guide 4.4).

## Content that ships, and what is yours to write

The content is a working minimum, and the tests check it hangs together:

- `agent-guidance/agents-md/base.md` holds a few fleet rules and a
  `## <Your lessons>` section to fill. `eval-coverage.yml` has one row per
  `##` heading with its byte count (`tests/check-coverage.py` checks both;
  update the row when you edit a section).
- `agent-skills/plugins/<you>-coding-anywhere/` holds the two skills above.
  `tests/test-layout.py` checks `scripts/plugin_layout.json`, each SKILL.md
  `name:` and the marketplace agree with the folders.
- `skills-evals/evals/` holds the two fixtures; `evals/scheduled.yml`
  schedules `workflow-path-audit/basic` and keeps the `example-skill`
  template a draft. `tests/test_shipped_fixtures.py` loads every fixture and,
  where it has a `solution/`, checks it fails on the seed and passes solved.
  The harness's own tests keep a separate copy of the guide's example fixture
  under `skills-evals/tests/fixtures/repo/`, so they never depend on what
  `evals/` holds.
- Environments and Apps are set up by the bootstrap scripts
  (`../bootstrap/`), not here.

Your own lessons, skills and fixtures replace or join these.

## Running the tests

- **agent-guidance**, **agent-skills**, **agent-skills-private**,
  **repo-settings**, **machine**, **cloud**: bash, git and python3 (PyYAML
  for agent-guidance, repo-settings and machine; jq for agent-skills and
  repo-settings). The
  end-to-end hook test in `machine/` needs git 2.54 or newer and says SKIP
  otherwise. Every test uses scratch git repos, a scratch `HOME` and
  `GIT_CONFIG_GLOBAL`, fixed commit times, no network and no sleeps.
- **skills-evals**: `pip install -r requirements-dev.txt` (exact pins).
  `tests/run.sh` runs `python3 -m pytest` (tests/ plus
  `scripts/test_dashboard_refresh.py`, as `pytest.ini` says) inside
  `unshare --user --map-current-user --pid --fork --mount-proc --` when the
  host allows it, so nothing the suite signals can reach a process outside.
  Every git call and check command the harness runs gets its own scratch
  `HOME` and empty global git config, never `/dev/null`.
  `tests/test_dashboard_page.py` drives `dashboard/index.html` in headless
  Chromium through node's `playwright` package (`npm install -g playwright`
  and `npx playwright install chromium`); without them it is skipped and
  pytest says why.

Read a test command's exit code directly, not through a pipe.

## The dashboard

`bash skills-evals/scripts/build-dashboard-site.sh <checkout of persistent/eval-results>`
writes `runs.json`, `allowance.json`, `gates.json` and `manifest.json` into
`skills-evals/dashboard/data/` (ignored by git) and prints the
`python3 -m http.server` command that serves the page. The page has no
external scripts or styles, and writes every dataset value as text.
